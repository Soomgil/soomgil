# 제품 경험 전환 정책

이 문서는 홈, 선호도 수집, 여행방 투표, 지도 협업, 커뮤니티 구조 전환에 대한 최신 제품 결정을 기록합니다. 기존 문서와 충돌하면 이 문서를 우선하며, 세부 계산은 `preference_tagging_policy.md`, 백엔드 계약은 `.agent/contracts/backend_contract_decisions.md`를 따릅니다.

## 내비게이션과 커뮤니티

- 전역 `기록` 탭과 독립 `취향 수집` 탭을 제거합니다. 여행방에 묶인 기록 데이터 자체의 삭제를 의미하지는 않습니다.
- 홈은 관광지 사진을 전체 배경으로 보여주고, 사용자가 좋아요/취소로 선호 신호를 남기도록 유도합니다.
- 커뮤니티는 기존 여행기 게시물/스토리 발행 형식을 종료하고 `thread + reply` 형식으로 전환합니다.
- 공개 API와 화면 용어는 `post`, `story` 대신 `thread`를 사용합니다. 기존 게시물 계약은 마이그레이션 대상입니다.

## 회원가입 선호도 수집

- 모든 신규 사용자에게 운영자가 버전으로 관리하는 동일한 관광지 10개를 보여줍니다.
- 10개 모두에 `LIKE` 또는 `NOPE` 반응을 제출해야 회원가입 선호도 단계를 완료할 수 있습니다.
- 관광지는 `provider + external_place_id`로 식별합니다.
- 설문 버전, 후보 관광지 순서, 사용자 응답과 완료 시각을 보관합니다.

## 선호도 데이터

- 수집 경로는 `ONBOARDING`, `HOME_BACKGROUND`, `TRIP_VOTE`이며 필요하면 코드 관리 값으로 확장합니다.
- `ONBOARDING` source multiplier는 초기 취향 신호를 강화하기 위해 `3.0`으로 적용합니다. `HOME_BACKGROUND`와 `TRIP_VOTE`는 `1.0`입니다.
- 반응 강도 차이는 수집 경로 가중치와 별개입니다. `SUPER_LIKE`는 `LIKE`보다 강하고 `NOPE`는 부정 근거입니다.
- 최종 사용자-장소 반응과 append-only 이벤트 로그를 함께 저장하고, 현재 태그 선호도는 materialized projection으로 유지합니다.
- 좋아요 취소는 제거 이벤트를 남기고 현재 반응 상태를 해제합니다. 과거 이벤트는 삭제하지 않습니다.
- 이벤트에는 source, source resource id, 정책 버전을 기록해 재계산할 수 있어야 합니다.

## 여행방 참여와 투표

- 역할은 `OWNER`, `MEMBER` 두 가지입니다. 저장된 membership role은 기존 계약처럼 `MEMBER`로 두고 OWNER는 `owner_user_id`에서 파생할 수 있습니다.
- 초대 링크/코드 수락으로 참여가 확정됩니다. 초대와 여행방 권한은 기존 구현을 그대로 재사용하고 새로 만들지 않습니다.
- 투표는 여행방당 하나의 세션으로 관리하고, 참여 상태는 세션별로 `NOT_STARTED`, `IN_PROGRESS`, `SUBMITTED`를 사용합니다. 첫 진입 여부를 boolean 하나로 두지 않습니다.
- 방장이 투표를 시작하면 그 시점의 활성 참여자 전원이 투표 참여자로 확정됩니다. 이후 합류한 멤버는 참여자로 추가하지 않습니다.
- 투표가 열려 있고 아직 제출하지 않은 참여자가 여행방에 들어오면 지도보다 투표 화면을 먼저 보여줍니다.
- 스티커를 제출한 사용자는 투표가 종료될 때까지 대기 화면을 봅니다.
- 투표가 끝난 사용자와, 이미 완료된 투표에 나중에 들어온 신규 참여자는 바로 지도 화면으로 갑니다.
- 어떤 화면을 먼저 보여줄지는 서버가 `nextScreen`(`VOTE`, `WAITING`, `MAP`)으로 계산해 내려주고 클라이언트는 그 값만 보고 분기합니다.
- 방장은 투표 시작 전에 사용자별 스티커 개수와 최종 선정 관광지 개수를 정합니다. 두 값은 투표 시작 후 변경할 수 없습니다.
- 두 값 모두 후보 관광지 수를 넘을 수 없습니다.
- 한 사용자는 총 지급량 안에서 같은 후보 관광지에 여러 스티커를 몰아 붙일 수 있습니다.
- 스티커를 1개 이상 사용하면 개인 투표를 제출할 수 있습니다.
- 제출 전에는 스티커를 이동하거나 회수할 수 있고, 제출한 뒤에는 수정할 수 없습니다.
- 후보 관광지는 방장이나 참여자가 직접 추가하거나 삭제하지 않습니다. 여행 지역과 모든 활성 참여자의 누적 취향을 바탕으로 추천 시스템이 자동 구성하며 기본 10개입니다.
- 투표 시작 시점의 후보를 세션 snapshot으로 고정해 투표 도중 추천 결과가 바뀌어도 후보가 변하지 않게 합니다.
- 여행방 안에서 다른 참여자의 취향 점수나 세부 태그는 노출하지 않습니다. 진행 중에는 후보별 스티커 중간 집계도 보여주지 않습니다.
- 방 전체 투표는 전원 제출 시 자동 종료하거나, 방장이 미투표 참여자가 있다는 경고를 확인한 뒤 조기 종료합니다. 마감 시각 기반 자동 종료는 사용하지 않습니다.
- 마지막 제출과 방장 조기 종료가 동시에 발생해도 종료와 결과 반영은 각각 한 번만 일어납니다.
- 득표순으로 선정하고 마지막 순위가 동점이면 동점 관광지를 모두 선정합니다. 스티커를 받지 못한 후보는 선정하지 않습니다.
- 선정 여부와 무관하게 사용자가 스티커를 붙인 모든 관광지는 `TRIP_VOTE` 출처로 개인 취향에 반영하며 장소별 스티커 개수를 보존합니다.
- 선정 관광지는 여행당 하나인 `UNSCHEDULED` 일정 그룹에 확정 방문 아이템으로 추가합니다. 이미 같은 여행에 존재하는 관광지는 중복 추가하지 않습니다.

## 지도 협업

- 영구 상태 조회와 변경 저장은 REST, 실시간 상태 전달은 STOMP over WebSocket을 사용합니다.
- 지도 오브젝트는 조작 종료 시 서버에 저장하고 드래그 중간 상태는 preview 이벤트로만 전달합니다.
- 같은 오브젝트는 먼저 편집을 시작한 사용자에게 임시 잠금을 부여합니다. 세션 종료나 lease 만료 시 잠금을 해제합니다.
- 재접속 시 서버의 최신 저장 상태를 기준으로 로컬 상태를 다시 동기화합니다.
- 같은 여행방의 접속 중인 사용자 커서를 모두 표시합니다. 커서 좌표는 세션 중에만 중계하고 영구 저장하지 않습니다.
- 지도에는 기본 스티커와 사용자 업로드 이미지를 배치할 수 있습니다.
- 업로드 이미지는 JPG, PNG, WebP만 허용하고 파일당 최대 10MB로 제한합니다. 저장 전 MIME 검증, 메타데이터 제거와 리사이징을 수행합니다.

## 계약 기본값

| 항목 | 기본값 |
| :--- | :--- |
| 회원가입 평가 관광지 | 고정 10개, 전부 응답 필수 |
| 수집 경로 가중치 | `ONBOARDING=3.0`, `HOME_BACKGROUND=1.0`, `TRIP_VOTE=1.0` |
| 사용자별 투표 스티커 | OWNER가 투표 시작 시 지정. 시작 후 변경 불가 |
| 최소 투표 사용량 | 1개 |
| 투표 후보 관광지 수 | 기본 10개. 추천이 자동 구성 |
| 선정 관광지 수 | OWNER가 투표 시작 시 지정. 시작 후 변경 불가 |
| 동점 | 마지막 순위 동점자 모두 선정 |
| 투표 종료 조건 | 전원 제출 자동 종료 또는 방장 조기 종료 |
| 지도 이미지 | JPG/PNG/WebP, 최대 10MB |
